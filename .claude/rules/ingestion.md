# 수집 규칙

## 주기
- 배치 — 하루 1회(또는 실습 중에는 수동 실행)
- 원본 데이터 자체가 실거래 신고 기준 월 단위로 갱신되므로, 더 잦은 수집은 의미가 없다

## 재시도
- OpenAPI 호출 실패 시 최대 3회, 5초 간격 재시도
- 3회 모두 실패하면 에러를 로그로 남기고 다음 배치로 넘어간다 (전체 파이프라인을 멈추지 않는다)

## 중복 적재 방지
- 월 단위로 통째로 바꿔 넣는다: 한 트랜잭션 안에서 그 지역·그 달 행을 지우고 API 결과 전체를 넣는다. 수집이 실패하면 아무것도 지우지 않는다(기존 행 유지)
  - 이유: 계약 해제는 신고 뒤에 나중에 표시되고 해제 건의 trade_id가 바뀌므로(`-c…`), 행 단위 UPSERT로는 예전 정상 행이 남는다
- `trade_id`는 PK라 같은 달을 여러 번 수집해도 행이 늘지 않는다

## API 응답 처리
- 응답 태그는 영문(`aptNm`, `dealAmount`, `excluUseAr` …)을 기본으로 읽고, 예전 한글 태그(`아파트`, `거래금액` …)도 함께 지원한다
- HTTP 200이어도 `resultCode`가 `000`/`00`이 아니면 오류로 처리한다
- `totalCount`가 한 페이지(`numOfRows`)보다 많으면 다음 페이지까지 모두 가져온다
- 여러 달은 `--from YYYYMM --to YYYYMM`으로 한 번에 수집한다
- 적재 전 원본 응답을 그대로 보관하지 않는다 — 정제된 컬럼만 저장한다 (원본 보관이 필요하면 별도 raw 테이블/파일로 분리 — 이번 캡스톤 범위 밖)
